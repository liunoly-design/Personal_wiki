## 执行与恢复

- 已安装用户级 CLI launcher、用户技能目录的 personal-wiki skill 和独立配置。凭据仍由受保护文件内部读取，配置权限0600，不复制旧飞书任务空间。
- 正式程序从私有版本化 release 执行；开发 session 使用独立、干净的项目 checkout，无法把未测试开发工作直接当作运行版本。
- 本机 `com.personal-wiki.ingestion` LaunchAgent 已启动。先提交一个仅转换的合成任务，再启动 worker，任务恢复为 converted，没有写 Wiki。
- 对该 worker 执行受控重启后确认新进程运行；再次按原 ID 核验三个真实样本均为 complete，原件和 Wiki 全文核验通过，旧失败提示清除。
- 自检返回 Wiki ready、Mini media ready、maintenance configured。整机重启和 Mini Wiki 接管没有在本轮执行，不以 worker 重启代替整机验收。

## Codex 维护验证

1. 故障与待补成员持久化，按处理器版本/故障聚合。记录更新使用独立锁；项目级 lease 串行化同开发 checkout 的修复。
2. 使用真实 Codex CLI 的持久开发 session，在独立的合成项目修复故意损坏的处理函数。实际 session 接收确认、独立行为测试、外层提交及 release 启用均成功；没有使用真实资料或真实 Wiki。
3. 验证发现 sandbox 内不能提交 Git，因此 Git 提交归外层程序持有：先绑定修复前 HEAD 与待测工作树，独立回归，检查没有并发变化，外层提交并校验 tree 后才启用。
4. 同一候选若由子 session 自行改写 Git 历史会拒绝；负例表明已提交的私有 raw 文件不会绕过检查进入运行 release。
5. 测试失败保持旧 release。开发 checkout 忙时进入退避队列；晚加入任务从持久成员列表补处理。来源锁忙时保持未执行，未知结果等待核对，不递归创建新的开发 session。
