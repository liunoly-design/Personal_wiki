# 0.3.0 开发任务拆分（已确认）

用户已于本轮确认计划。需求见 [0.3.0 规格](../specs/v0.3.0-collection-reading.md)，已发布为 [Issue #2](https://github.com/liunoly-design/Personal_wiki/issues/2)。11 项开发任务已按依赖顺序发布为 #3–#13，均带 ready-for-agent 标签，尚未实施或验收。当前连接器没有原生依赖/子任务关系写入工具，Issue 正文使用真实链接记录 Parent 和 Blocked by。

## 拆分原则

- 每项交付一条从用户输入到可见产物或状态的完整路径。
- 基础收集流程已存在，任务直接在该路径增加行为，不单独安排空泛框架建设。
- T01 是长期知识写入的前置保护；T02 将既有路径接为专用 Agent 工具。
- T03–T08、T10 可以在依赖完成后分别推进；T09 是跨阶段故障恢复，T11 才做全组合及真实入口验收。
- 新接口的基本失败处理在各功能任务中实现，T09 不用于推迟它们的必要错误处理。
- 不包含旧归档补译、远端备份、查询、讨论和后续文件导入。

## 每项任务复用 nashsu 的方式

以下以本机 nashsu 0.6.11 为准。API 直接整合仍需鉴权、固定项目、错误处理和业务验收；这里的区别是是否已有对应知识能力，而不是是否完全不用编写集成代码。

| 任务 | 实现类型 | 复用与需补齐内容 |
|---|---|---|
| T01 | 复用上游编译，补写入保护 | 继续使用 nashsu 的资料卡、概念、实体与关联编译；补足原件/手写保护、冲突保留和受控提交。没有一个 HTTP 调用可以保证全部保护要求。 |
| T02 | HTTP API 整合＋业务适配 | 使用 health/projects 验证项目；T01 实测后改为复用固定上游提示词及解析器做受控编译，不对新来源调用 sources/rescan。任务状态、固定项目、Agent 工具及飞书回执由现有适配层补齐。当前没有通用 HTTP 编译队列进度接口，不能以 rescan 成功表示处理完成。 |
| T03 | 扩展现有入口和归档器 | 复用现有指令路由、归档、哈希和去重实现；新增文本、多链接、背景和显式重收集的入口行为，后续知识加工仍交 nashsu。 |
| T04 | 复用采集库，补博客适配 | 复用已有文章提取和附件下载库；nashsu 的剪藏入口接收已提取内容，不能直接替代博客 URL 抓取。归档后继续使用 nashsu 编译。 |
| T05 | 复用 CLI 调用方式，新增翻译流程 | 复用已有 Codex CLI 接入方式，逐次指定 gpt-5.6-terra；nashsu 中文知识输出不是全文翻译 API。补长文完整性、忠实排版、独立状态和单独补译。 |
| T06 | 扩展现有 X 采集适配 | 复用现有 X 正文识别与附件抓取，增加同作者串文和远端引用展开；nashsu HTTP API 没有此平台采集能力。 |
| T07 | 复用浏览器能力，新增恢复衔接 | 选择并验证现成浏览器/会话接入方式，补登录失效与恢复任务状态；不是 nashsu HTTP API 提供的浏览器登录功能。 |
| T08 | 扩展现有下载器和附件状态 | 复用已接入的图片/视频下载能力，补下载前及下载中阈值控制与单独补下载；无对应的一站式 nashsu HTTP 接口。 |
| T09 | 复用现有队列，补统一恢复 | 复用本项目任务队列和受控编译记录，统一总尝试预算、等待状态及跨阶段恢复；不能仅把外层重试次数改为五次。 |
| T10 | HTTP API 整合＋待审动作适配 | 直接复用 GET reviews、PATCH reviews/{id} 与 POST reviews/resolve 的查询/状态能力；实际应用动作、并发保护、历史和编号交互仍需适配。状态更新成功不等于动作执行成功。 |
| T11 | 复用测试与实测基线，补整体验收 | 沿用已有归档、幂等、路由和 nashsu 样本验证；新增完整来源组合、翻译、恢复和真实飞书链路的验收，不重造知识引擎。 |

0.4.0 的 search/read/graph 和待审列表查询是最适合直接整合 HTTP API 的部分。0.3.0 的核心知识编译复用上游的纯提示词与解析器。T01 实测发现桌面自动编译不能保证手写保护，因此新来源改走 raw/inputs 与受控提交，不触发监听或 rescan。详见 [保护实现](../development/protected-compilation.md)。PDF/Office 转换属于后续版本的桌面能力复用；当前没有对应通用 HTTP 转换接口。

证据见 [API 与能力映射](../research/nashsu-capability-mapping-2026-09-27.md)及 [版本规划中的接口表](../implementation-roadmap.md)。

## 任务详情

### T01：编译资料时保护原件、人工内容与历史

**对应功能**：F02、F03、F09  
**Blocked by**：无，可开始  
**交付**：提交一个合成来源，复用 nashsu 得到带引用知识页；已有原件、手写及保留段落不被覆盖，冲突或不明归属转待审。

- [ ] 原件与附件哈希保持不变，来源引用可解析。
- [ ] 新旧冲突观点保留来源与日期；AI 更新有历史。
- [ ] 包含并发手写修改的样本；不能可靠判断时生成建议而不覆盖。
- [ ] 先在隔离样本验证上游写入保护，不能只修改提示词。

### T02：通过专用 Agent 工具记录资料并查询进度

**对应功能**：F01、F04、F12  
**Blocked by**：T01  
**交付**：现有单链接收集经专用业务工具进入同一可靠流程；用户能看到接收、归档和编译的真实状态。

- [ ] 固定项目 ID、核对目标 Vault，桌面切换项目不误写。
- [ ] 使用受控编译的持久结果判断完成；不以 HTTP 扫描成功表示完成（T01 实测调整）。
- [ ] 保留既有指令路由与消息幂等；Agent 不取得令牌或任意写入能力。
- [ ] 完成回执包含标题、摘要、位置与实际附件结果；应用未运行时状态明确。

### T03：接收文本、多链接、个人背景与显式重新收集

**对应功能**：F02、F05  
**Blocked by**：T02  
**交付**：一条收集消息中的文本或多个链接分别归档，个人背景单独保存；重复复用，明确重收集时保留变化版本。

- [ ] 保留现有指令与已确认别名，仅按明确入口触发。
- [ ] 单项失败不丢失其他成功项，回执逐项显示结果。
- [ ] 相同内容重复投递不重复模型调用；变化原文保留旧哈希与版本。
- [ ] 可读英文短文件名、同名版本及引用维护符合已有要求。

### T04：收集普通国外博客正文及附件

**对应功能**：F15  
**Blocked by**：T02  
**交付**：发送普通博客 URL，保存原始响应、完整正文提取稿、图片和来源卡。

- [ ] 优先复用现成文章提取库，保留标题、正文层级和图文顺序。
- [ ] 公开博客包含正文、重定向、缺图和提取不完整样本。
- [ ] 正文不完整或附件失败明确为部分完成，不推断未取得的内容。
- [ ] 原件、提取稿与资料卡分别可定位，重复 URL 复用。

### T05：为新英文来源生成完整中文阅读正文

**对应功能**：F11  
**Blocked by**：T02  
**交付**：收集英文文章后取得完整中文译文及原文入口，中文文章忠实排版；翻译失败继续原文知识加工并支持单独补译。

- [ ] Codex CLI 单次指定 gpt-5.6-terra，保留既有基础解释和知识编译模型职责。
- [ ] 长文不漏节，表格、图片、代码、公式、链接及正文顺序保留；不摘要化。
- [ ] 原件、译文、资料卡同属一份来源，译文不作为新增独立证据重复编译。
- [ ] 翻译与知识状态独立，单独补译不重复抓取或知识加工；旧归档重复投递不补译。
- [ ] 以既有 X/微信或文本样本先验收，不人为依赖博客采集任务；T11 验收博客组合。

### T06：完整收集 X 同作者串文及引用帖

**对应功能**：F06  
**Blocked by**：T02  
**交付**：记录目标 X 链接时保留同作者连续串文和引用帖，排除其他评论。

- [ ] 覆盖分页/多条、引用远端内容、评论干扰和重复节点样本。
- [ ] 每段正文和附件可回到对应帖子来源，不把评论当正文。
- [ ] 上下文不可读取时保留已取得内容并说明缺口，不伪造完整串文。

### T07：使用本机登录会话并在失效后续作

**对应功能**：F06、F08  
**Blocked by**：T02  
**交付**：需要登录的来源进入明确等待状态，用户恢复会话后继续同一任务。

- [ ] 用隔离会话或获准样本实测选择现成浏览器接入方式，记录选择依据。
- [ ] 登录失效/验证码暂停，向原会话报告所需操作；不当作普通网络错误循环重试。
- [ ] 恢复后保留已下载内容和原件，不扩大其他私人账户访问。
- [ ] 真实会话使用与外部消息按具体授权执行；模拟通过不冒充真实验收。

### T08：视频超限暂停与失败附件单独补下载

**对应功能**：F07  
**Blocked by**：T02  
**交付**：收集时遵守既定视频限制，超限等待确认；正文成功而附件失败时可仅补附件。

- [ ] 最高 1080p；超过 30 分钟或预计 1 GB 先暂停，未知大小达到 1 GB 暂停。
- [ ] 暂停或失败仍保留正文和已有成功附件，回执列出待处理项。
- [ ] 补下载不重新抓取正文或调用知识模型，不自动展开播放列表、不转录视频。

### T09：统一重试预算、额度等待和处理中恢复

**对应功能**：F08  
**Blocked by**：T02、T05、T07、T08  
**交付**：对已接入的处理阶段进行故障恢复验收，网络失败不超过五次，额度不足等待，崩溃后只继续未完成阶段。

- [ ] 消除外层、采集库与编译队列的重试倍增；记录实际尝试次数。
- [ ] 模型不可用/额度不足不自动切换付费 API，成功阶段不重复执行。
- [ ] 覆盖采集后、归档后、翻译中、编译中、附件中与回执前后中断。
- [ ] 对其他采集器采用共同处理契约；T11 验证完整来源组合，不人为依赖所有平台开发任务。

### T10：按编号应用、跳过或稍后处理待审

**对应功能**：F10  
**Blocked by**：T02  
**交付**：用户收到待审编号并提交处理指令，只有指定动作成功后才更新状态，修改保留历史。

- [ ] 复用 nashsu Review 数据，稳定映射用户编号和实际建议。
- [ ] 真实执行并校验应用动作，不能仅将 resolved 标为 true。
- [ ] 跳过/稍后不修改知识正文；过期版本、桌面并发冲突及不支持动作保留待审并说明原因。
- [ ] 综合文章和大范围修改继续走已确认待审边界。

### T11：完成 0.3.0 全链路验收与交付记录

**对应功能**：F01–F15 中属于 0.3.0 的项目  
**Blocked by**：T03、T04、T06、T09、T10  
**交付**：按实际飞书入口验证文本、X、微信和博客的收集、中文阅读及恢复，记录真实交付版本。

- [ ] 运行适当自动测试与少量已授权真实集成，检查原件、阅读正文、资料卡、链接与回执。
- [ ] 覆盖博客＋翻译、批量＋部分失败、待审＋人工保护、重复旧归档不补译等组合。
- [ ] 真实入站和最终回执必须有对应证据，外部动作授权不足时保留未验收状态。
- [ ] 按固定基点运行规范/规格双轴 code-review，问题修复后再更新交付说明和实际版本。

## 审阅结论

用户已确认上述计划。已按确认顺序发布到配置的 GitHub 仓库，关联规格并记录真实依赖；原规格 #1 和 #2 均保持开放且未修改。新增的复用说明用于明确实施方式，不改变已确认范围和依赖。当前无阻塞的首项为 T01 / #3。
