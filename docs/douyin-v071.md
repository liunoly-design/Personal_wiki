# 0.7.1 飞书抖音远程处理

本版把飞书“小婕 wk 记录”接到 Mac mini 的v1媒体服务；视频与完整音频远程保存，文字及其元数据通过现有受保护发布进入Wiki。旧0.7.0本地云ASR流程仅作历史候选。部署及真实入站状态见 [部署验收报告](research/v0.7.1-remote-deployment-2026-10-05.md)。

直接粘贴完整抖音分享文案：

```text
小婕 wk 记录：8.46 复制打开抖音，看看【evan.的作品】Claude Code 的工程师刚发布了一段 28... https://v.douyin.com/emjiIYoJWK8/ 02/28 :1pm y@G.VY pDU:/
```

仅链接同样支持，但不要求用户清理分享文案。末尾紧贴标点会剥离，重复链接去重。明确的个人说明另起“备注：”；抖音自动分享文案不当作个人观点。口令是wk。

先返回收到与本机任务编号，后续核验正式资料、全文API读回和搜索后返回完成回执。源音轨为英文时同时保存英文原稿和完整中文机器译文，保留真实模型/语言和时间戳。文字未经人工校订，不将机器稿视为已核实事实。

收到等待回执时：

```text
小婕 wk 状态：<本机64位任务ID>
小婕 wk 继续：<本机64位任务ID>
```

远程任务ID为诊断信息，不能替代本机任务ID。恢复使用持久远程job_id，不盲目重交或重复转写。远程登录、额度/确认等在Mac mini处理，恢复后用上述“继续”。超过30分钟/1GB的服务端确认接口尚未实现，本机不会自动批准。显式重新收集目前需服务端先产生新的处理版本，不能把复用旧转写称为刷新成功。

完成后可发送：

```text
小婕 wk 查询：Claude Code 工程实践
```

用正文里的精确短语可验证全文检索。查询/阅读沿用现有权限与来源编号；视频、音频稳定URL需要认证，不把长期令牌或临时播放能力写进Wiki/聊天。本机不保存完整视频或音频。Wiki编译沿用现有模型配置，远程ASR/译文不会在本机重复生成。

服务配置只有 mediaServiceUrl 和 mediaServiceTokenFile，后者为本机受限文件路径，令牌内容从不进入配置、仓库或日志。0.6.2 release及部署前配置备份保留；禁止恢复旧配置时覆盖用户后来修改的其他设置。
