# 受控编译开发记录

开发分支：`codex/wiki-v03`。当前为 T01 的开发实现，尚未部署到运行中的 OpenClaw，也不是 0.3.0 全部功能交付。

## 复用与调整

固定 nashsu v0.6.11 / `e8082119649e6a8e1cf85eaf289adcabfdf39d4e` 的分析、生成提示词及 FILE 解析器。提取代码与完整 GPL-3.0 许可证在 `vendor/nashsu/`。中文输出显式固定；知识编译模型沿用 `gpt-6-sol`，可通过 `compilerModel` 配置；全文翻译在独立阅读流程中指定 `gpt-5.6-terra`，见 [中文阅读开发验收](chinese-reading.md)。

0.6.11 没有安全的无界面候选编译 API。桌面自动编译会直接写页，所以本实现不把新来源送入 `raw/sources`，也不调用 rescan。改为 Codex CLI 在临时目录、read-only sandbox 中产出文本，再由程序提交。CLI 忽略用户配置与规则、不持久化会话；应用配置和令牌不注入提示词。详见 [源码核查](../research/safe-ingest-options.md)。

## 文件与写入规则

- 原件与附件：`raw/assets/<内容版本 ID>/`；提取稿另存 `raw/inputs/<英文名>.md`，不加入桌面来源监听目录。
- 清单、SHA-256 和 URL 索引：`.personal-wiki/`。同一内容重收集复用版本；旧归档保持原样。
- 新的来源、概念、实体、主题页：原子创建，不替换任何已有页。
- 已有页或新综合文章：保存带原内容、原哈希、候选、来源和日期的待审记录，不改现有页。
- 编译输出、逐页候选和最终结果：`.personal-wiki/compilations/<来源 ID>/`，可追溯并用于中断后续作。
- 文件操作使用目录描述符、O_NOFOLLOW、进程锁和原子 hard-link 创建；原件及知识页不存在覆盖操作。只有本项目运行状态允许原子替换。
- 路径越界、符号链接、截断 FILE、重复路径或缺资料卡：失败并保留原件。完整 generation 文本也保存，后续待审任务可处理其中的 REVIEW。

## 范围与后续

T01 不声称已经实现可应用的 Review 交互、跨进程模型任务去重、全部阶段恢复、翻译、博客或真实飞书入站。现有页全部进入待审，避免通过模型猜测人工归属；自动增量合并留给安全的待审应用流程。

自动测试使用公开接口 `createAdapters.importAndCompile` 和隔离合成目录，检查原件、可读引用、并发手工编辑、候选记录、截断恢复、符号链接拒绝和索引恢复。真实 CLI 合成样本已通过：使用既有订阅的 `gpt-6-sol`，生成 1 个中文来源卡、2 个实体页和 1 个概念页；原始样本没有被修改。首轮因中文文件名被保护层拒绝，补明确英文命名约束后复测通过。可用 `scripts/manual/protected-compile.js` 重现，需显式提供本机 CLI 路径。
