# 0.6 飞书使用与验收

在已授权的“小婕”飞书会话发送。只查询本库，沿用现有订阅模型；请让一次回复结束后再发下一条。D是讨论编号、K是阅读编号、R是待审编号。下方`D-返回编号`、`K-返回编号`、`R-返回编号`必须替换为你收到的完整编号，不能直接发送占位符。

## 0.6.1 直接回复和保存全文

- **继续 Wiki 讨论**：在飞书对带有`【Wiki】讨论 D-…`的那条消息点击“回复”，直接写追问。沿用那条消息的讨论编号、历史和本库来源；不需要重抄口令。普通小婕分析不会自动成为 Wiki 讨论，需回复原 Wiki 消息或发送明确的`小婕 wk 讨论：D-实际编号 问题`。
- **保存某条长回复全文**：对要保存的小婕文本/富文本消息点击“回复”，发送`小婕 wk 保存`。保留指定消息的原 Markdown 和原始消息 JSON，新增正式阅读页；不重新摘要或分析。成功回执包含 K 阅读命令。
- **保存讨论结论**：`小婕 wk 保存结论：D-实际编号`整理已进入该 Wiki 讨论的问题、依据、结论、用户判断和未决问题。它与“保存某条回复全文”用途不同。
- 普通小婕长分析可以明确保存，但标注“模型回复、未经 Wiki 来源核验”，不作为作者证据或综合独立来源。单独发送`小婕 wk 保存`没有回复目标会拒绝猜测。
- 核验失败时对**同一条目标消息**重新回复`小婕 wk 保存`，恢复首次保存快照，不重复建篇；目标后来被编辑也不会覆盖首次原件。

## 完整顺序示例

1. **开始讨论**，复制发送：

   ```text
   小婕 wk 讨论：Opus 工作流适合什么场景，有哪些限制？
   ```

   预期：返回D编号、中文分析、已读来源引用与阅读命令。作者观点、模型推断、未决问题分开。资料不足明确说缺证据，仍保留同一讨论编号。不会把普通讨论写进正式库。

2. **追问并明确自己的判断**：

   ```text
   小婕 wk 讨论：这些观点在小团队和大型组织中有什么不同？
   用户判断：我暂时只考虑小范围试验，不直接推广。
   ```

   预期：继续同一个D编号，结合已读资料及新检索证据；你的判断按原话单独标注，不称为作者观点或行动承诺。若要指定某个旧讨论，使用`小婕 wk 讨论：D-返回编号 问题`。

3. **核对来源**。从回执复制完整阅读命令，例如：

   ```text
   小婕 wk 阅读：K-返回编号 1
   ```

   预期：真实Markdown正文，无YAML和逐行L前缀；页尾给本次原始行范围与下一页命令。引用中的L行号仍对应原文件。必要时补读具体片段后再讨论：

   ```text
   小婕 wk 讨论：请对照这两个来源，解释分歧和适用条件。
   来源：K-第一份编号 1, K-第二份编号 81
   ```

   替换K编号和起始行；每次最多5份。只能用当前会话已发现的编号，不能提供任意路径。原文和译稿属于同一来源；综合须有至少两份独立来源。

4. **明确保存结论**：

   ```text
   小婕 wk 保存结论：D-返回编号
   ```

   预期：新增一篇正式结论，包含讨论问题、引用依据、形成的结论、用户判断和未决问题。通过nashsu正文哈希回读与搜索发现后，返回K阅读命令。正式结论成为本库知识；未保存的原始交流仍在Vault外。

5. **生成综合草稿**：

   ```text
   小婕 wk 综合：D-返回编号 Opus 工作流的适用条件与限制
   ```

   预期：返回R编号，只生成待审草稿，正式综合文章尚未发布。只有一份独立来源时明确拒绝；继续讨论补充来源再试。同源译稿不凑数。

6. **查看并审阅草稿**：

   ```text
   小婕 wk 待审：R-返回编号
   ```

   预期：看到草稿内容、引用、目标与风险。查看不批准。核对作者观点、日期、冲突、用户判断和证据缺口；引用格式通过不等于每个事实语义都正确。

7. **确实接受才批准**：

   ```text
   小婕 wk 应用：R-返回编号
   ```

   预期：受保护发布并回读核验，返回K阅读入口和历史位置。基线改变或并发手写编辑时拒绝覆盖。只查看不想发布时可发送`小婕 wk 稍后：R-返回编号`；明确不采用可发送`小婕 wk 跳过：R-返回编号`。不要为了测试批准不想采用的真实建议。

8. **阅读结果、结束与换话题**：复制应用回执的`小婕 wk 阅读：K-实际编号 1`。再发送：

   ```text
   小婕 wk 结束讨论：D-返回编号
   小婕 wk 新讨论：我想讨论另一个主题。
   ```

   请分两条发送。结束只停止默认续聊，不自动保存。旧讨论可在同一授权会话用D编号恢复，不能在另一会话或另一用户下读取私人交流。

## 失败如何继续

- 模型/额度/API故障：外部条件恢复后，在原会话重发相同命令。系统复用仍可恢复的原请求；没有自动切付费API或无限后台重试。
- 保存已写入但核验失败：重发相同保存命令，核验同一候选，不生成第二篇。讨论未增加新回合时，多次保存或综合复用已完成结果；新增讨论后保存可生成新结论快照，旧版保留。
- 失败回合后已有新回合：旧消息不覆盖新上下文；重新发送问题作为新消息，按最新上下文回答。
- 待审应用核验失败：重发同一R应用命令，恢复现有动作；不要转“跳过”掩盖未核验内容。提案变更须重新查看再发新的批准消息。
- 无证据：补充已收藏文章标题/具体事实，或先`小婕 wk 查询：关键词`取得来源，再用“来源：”指定。不会自动联网补证据。
- 20轮、20片段或64KiB上下文限额：停止新增回合，完整旧上下文保留；先保存结论，再新讨论。不会静默删掉关键来源。

## 用户验收通过标准

依上面顺序实际发送后检查：同一D可追问与恢复；换话题不混入旧判断；来源正文与引用相符；普通讨论无正式文章；明确保存才读搜可见；综合未批准无正式页；批准后可读且原件/旧文保留；失败提示能按命令恢复。真实飞书布局、入站消息和用户语义抽样需你实际操作，本机函数调用不能替代。

记录异常时提供时间、命令、D/K/R编号及回执即可；不需要凭据或Cookie。0.4.2真实复杂X/私人登录、0.5此前未完成飞书重测依然各自待验收。
