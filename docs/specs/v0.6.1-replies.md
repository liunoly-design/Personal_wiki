# 0.6.1 飞书回复续聊与保存原回复

2026-10-03；基线a6f1ca6。用户真实反馈：对Wiki讨论的直接回复进入普通小婕分析；希望始终基于Wiki讨论，并通过回复“小婕 wk 保存”保存长结果。

已核实：首轮Wiki状态只有一个成功回合，实际追问的parent_id指向Wiki回执，但没有口令，插件未接管；后续长分析由普通Agent生成，无Wiki引用，不属于既有D上下文。此事实不等于其政策/数字已核验。

## 已授权修复行为

- 对小婕发出的已登记Wiki讨论回执直接回复普通问题，自动进入所回复的D讨论；不只依据当前active，不需再抄编号。原用户消息、parent_id、同一chat、own app_id、本用户/会话持久回执正文均须匹配。未知/伪造/其他模块回复不隐式进入Wiki；显式GTD/其他指令不接管。
- 对小婕文本/富文本回复使用飞书“回复”，发送`小婕 wk 保存`（兼容空冒号）。保存指定消息本身，保留原始消息JSON、原Markdown正文和正式阅读页；不另生成摘要、不重新分析。无被回复目标拒绝猜测；跨会话/其他app/删除目标拒绝。
- 这与`保存结论：D-编号`区别明确：后者整理已入Wiki讨论的结论，前者保存指定回复原文。普通Agent的长回复也可明确保存，但标注模型输出、未据Wiki来源核验，不能当作作者/政策事实证据或综合独立来源。
- 正式结果仅只增发布，复用Root、Vault锁和固定路径；原始JSON中的body.content保持字节内容。API回读正式页与原文、搜索发现通过才完成；失败保留候选，新消息重发保存同一目标时复用，原件不能改写。已有内容、附件与手写零覆盖。
- 注册wiki_discuss现有原消息工具支持回复保存；模型不能传任意路径、正文或被回复ID伪造用户批准。当前普通长回复不由开发者代保存；等用户在飞书明确发送保存口令。

## 验收

公共边界沿用原消息/插件hook→可见结果，合成TDD复现直接回复被忽略；测试同D续聊、换active后回复旧D、其他app/会话/假正文拒绝、富文本完整保存、零模型调用、API故障/重启恢复、重复同目标不双建、无reply拒绝、模型回复不算独立来源。真实消息与已有讨论状态只读复制到Vault外隔离状态回放；不向飞书代发消息，不保存真实正文到仓库。全回归、双轴复审后新不可变0.6.1发布，旧release保留。
