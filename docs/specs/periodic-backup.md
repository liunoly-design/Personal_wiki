# 每三天备份，失败飞书告警

任务：[#38](https://github.com/liunoly-design/Personal_wiki/issues/38)。固定基础提交 `5b9840a`。

用户已确认每三天一次、失败通过飞书通知；成功不发消息。沿用真实验收的源、Mini 目标、专用密钥、Python，以及当前唯一 Wiki 飞书用户与会话。

## 交付边界与验收

- 公共 seam：固定执行入口 `run/status`，执行现有备份 CLI 的 backup 和 verify。合成临时 Vault 验证成功静默、失败通知、最后成功时间保留、重放/并发/读回恢复及安全路径。
- 调度使用当前聊天的原生 heartbeat，上海时间每三天22:00，首次2026-10-10。状态保存 nextDue，早于到期不备份；错过后执行一次，不能连续补跑所有旧周期。成功或失败均进入下一个周期，无额外自动重试。
- 成功必须有目标完整校验；记录时间、ID、文件数、字节数，不通知飞书。
- 失败保留源、已提交快照和 pending；告警只含安全归类原因、失败时间、最后成功时间与恢复建议，不含原件正文、凭据和任意子进程输出。
- 通知使用当前明确授权的 Feishu 账号/唯一用户与会话，发送固定幂等键，API 读回检查发送应用、chat、内容。发送意图先落盘；未知发送不自动重复，有已知消息ID则只能重试读回。
- 同一 runId 不重做已完成备份/不重发告警；状态目录独立于 Vault，拒绝符号链接和路径逃逸；并发调用互斥。状态与凭据不进Git。
- 验收包括真实成功执行和一次清楚标注“告警测试”的受控失败消息；实际备份保持完整。启用原生自动化后读回配置。
- 来源 Mac 和桌面应用须运行，且可连 Mini 与 Feishu；机器/应用不运行时不能执行或当场发送失败告警。若飞书不可达，保留未知/失败通知凭据并由任务失败渠道提示，不假装已经送达。

不添加系统 cron/LaunchAgent，不改 Gateway 或其他账号，不自动清理旧快照，不把月内日期列表当作三天周期。
