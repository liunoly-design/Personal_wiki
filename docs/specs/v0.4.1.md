# Personal Wiki 0.4.1 SPEC

远端规格：[Issue #18](https://github.com/liunoly-design/Personal_wiki/issues/18)。

日期：2026-10-01；基线：2728da449c3bba985de598683cb02a67ec6f299d。

## Problem Statement

当前入口仅支持单条 X/微信 URL，无法收集公开博客、粘贴文本、多链接和个人背景，也不能显式刷新原文。

## Solution

扩展授权会话内的收集入口；每份来源独立持久化、加工、发布和核验。普通重复复用；明确重新收集才抓取，变化时保存新快照。保留单一正式资料库与原件保护。

## User Stories（已确认）

1. 作为用户，我希望发送公开国外博客，保存完整正文与图片，方便中文阅读。
2. 作为用户，我希望粘贴文本，保留收到的文本原件与来源卡。
3. 作为用户，我希望一次发送多个链接，每项独立处理，单项失败不影响其他项。
4. 作为用户，我希望附加个人背景，与原作者内容及证据分开。
5. 作为用户，我希望使用“小婕收集”及原有“小婕 wk 记录：”入口。
6. 作为用户，我希望重复投递复用归档，不重复调用模型。
7. 作为用户，我希望明确重新收集时检查变化，无变化复用，有变化保留历史。
8. 作为用户，我希望长文章逐节全文翻译，图片、表格、代码、链接与顺序保留。
9. 作为用户，我希望失败和中断保留原件及任务，API 核验前不清理。
10. 作为用户，我希望手写页和旧原件保持原样。

## Implementation Decisions（工程决定）

- 复用现有消息校验、持久队列、采集适配、中文阅读、受保护发布及原生 API 核验。
- 每条消息按稳定项序号分配任务 ID；同源互斥，完成凭据按来源保存。文本使用内容哈希来源 ID。
- 支持“小婕收集”“小婕 收集”“小婕 wk 记录：”；显式“重新收集”修饰动作。备注/背景标签后的文本是个人背景；链接消息的其他文字亦作为背景。纯文本消息整体作为原文，只有显式备注标签分隔背景。
- 个人背景保存为独立用户记录，不送入原文翻译或知识证据加工；重复资料亦保存本次背景。
- 博客复用 readability-lxml、BeautifulSoup 与 markdownify，选择 article/main/正文容器，缺乏可靠容器时标记提取待确认；不猜测缺失正文。
- HTTPS 请求逐跳校验公网地址、端口和凭据，固定连接到已验证地址以防 DNS 重绑定；图片同样受控，限流、超时、大小限制和最多五次尝试。
- 刷新比较正文和附件原始字节，采集时间不参与变化判定；原始 HTML 的变化作为新快照依据。模型只在新快照上调用。
- 部分正文/附件结果保留在工作区并标记等待；不宣称完整成功。公开缺图可发布正文与明确缺失清单，未取得内容不作证据。

## Testing Decisions / Acceptance

沿用已批准任务 #5/#6 的外部业务边界：输入消息/指令 → 可见产物、任务状态、回执、引用与哈希。使用合成采集器、模型及 API 在既有公开边界验证，不测试私有实现。

- 多链接部分失败后成功项完整保存；重复消息不增加任务。
- 文本原件逐字保存；备注不进入原文或模型证据输入。
- 普通重复零采集/模型调用；显式刷新无变化零模型调用；有变化保存新版本与旧哈希。
- 公网重定向成功，内网/非 HTTPS/凭据/不支持端口拒绝，缺图明确标记。
- 长正文末节、标题、表格、代码、链接与图片完整；成功翻译阶段可恢复。
- API 失败保留工作区；恢复核验后才清理；人工内容原样保留。
- 发布到新不可变 release；插件 loaded、网关健康、启动恢复、API 读取/搜索通过。

## Out of Scope

复杂 X 串文/远端引用、登录恢复、媒体补下载交互（0.4.2）；飞书查询/待审动作（0.5）；讨论、文件导入、转录及定期备份。旧归档不补译，不自动切付费模型，不发送未经授权的测试消息。

## Further Notes

已确认需求来自交接和 #5/#6，工程决定不扩展账号或外部消息权限。真实飞书新入站由用户发起；未覆盖时作为用户验收项。父规格 #14 保持开放。
