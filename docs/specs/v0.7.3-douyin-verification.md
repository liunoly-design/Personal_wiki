# 0.7.3 抖音来源、完整性与失败诊断

用户已授权修复下载错误风险，并明确每条消息仅发一个链接。整段分享文案继续支持；相同URL重复出现去重，出现两个不同URL且包含抖音时拒绝，不选第一个。其他平台多链接行为不改变。

## 客户端必须检查

- manifest.source.url 为规范 `/video/{source.id}` 地址，标准HTTPS端口。
- manifest.verification.input_url 与实际提交链接一致；链接显式作品ID（path/modal_id/item_id）均与source.id一致。
- verification.resolved_id/detail_id/downloaded_id 与 source.id 全部一致。
- verification.video/audio 都为 full_decode=true，实际 sha256/bytes 与 manifest.media 对应值一致，duration_seconds 为有限正数。
- 视频与音轨、视频与 source.duration_seconds 差值均不超过 max(1秒, 视频时长×0.5%)。
- 已有 Markdown 哈希及中文逐条校验继续执行。缺少证据、来源不符、完整解码失败或时长不符暂停，不继续发布或自动重交。
- Range 检查按 manifest 文件大小检查开头、中间和末尾，每次最多16字节，所有 Content-Range 与字节数准确。Range不替代完整解码。
- 服务端失败显示白名单阶段、错误码、retryable及原job_id，不显示服务端原始message。未知值显示unknown/UNKNOWN。服务健康不等于任务成功；重复继续不会自动修复原因。

## 服务端必须同步

既有v1接口不变。每份成功manifest增加下面的verification；由实际处理阶段生成，不能为兼容客户端填常量或猜测。source.id为抖音作品ID，downloaded_id指该媒体下载请求绑定的作品ID，不是文件UUID。

```json
{"verification":{"input_url":"https://v.douyin.com/example/","resolved_id":"7691977131957472558","detail_id":"7691977131957472558","downloaded_id":"7691977131957472558","video":{"full_decode":true,"sha256":"实际视频SHA256","bytes":123456,"duration_seconds":600.0},"audio":{"full_decode":true,"sha256":"实际音频SHA256","bytes":12345,"duration_seconds":600.0}}}
```

保留分享链接解析记录、详情原始JSON、下载绑定及完整FFmpeg解码结果为私有诊断证据。计算实际文件哈希/字节数，保存probe时长。视频或音轨不能完整解码时不标succeeded；原件与已验证阶段保留，恢复同一job。不重新下载或转写已验证且哈希未变的产物。

GET /v1/jobs/{id} 可添加 stage，使用 resolving/metadata/downloading/extracting/transcribing/translating/verifying。error.code 使用 SOURCE_RESOLUTION_FAILED/DETAIL_FETCH_FAILED/SOURCE_UNAVAILABLE/AUTH_REQUIRED/DOWNLOAD_FAILED/MEDIA_INVALID/EXTRACTION_FAILED/ASR_FAILED/TRANSLATION_FAILED/VERIFICATION_FAILED/SOURCE_MISMATCH/PROCESSING_FAILED。retryable按真实恢复条件设置布尔值，不把未知结果误称可重试。客户端不回显原始message。

服务端验证：错误链接映射、错误详情ID、错误下载ID、截断视频、缺音轨、时长不符、错误哈希、失效鉴权、空译文、误标语种均不得通过；阶段恢复保留原任务ID及原件。同作品不同分享链接由服务端按最终作品ID与处理参数去重，冲突或未知提交不得盲目重新处理。

## 验收及边界

继续使用已约定parseCommand、MediaServiceClient实际HTTP及collectCanonical受保护发布入口测试。客户端只能核验服务器提交的证据的一致性；服务器若错误或伪造证据，客户端不能独立证明远程媒体的真实性。服务器完整解码、作品绑定及跨设备验证都是必需项。

未同步verification的旧服务器会被新客户端拒绝发布（verification evidence missing; upgrade server），不是网络故障。历史已完成资料不重写、不迁移、不重新处理。旧服务端跨设备验收不算0.7.3通过。
