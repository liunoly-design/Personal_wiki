# 0.7.0 抖音视频、音频与全文转录

日期：2026-10-04（Asia/Shanghai）。状态：用户已完成grill并确认Q2–Q10、保存规则例外及业务入口验收；to-spec定稿，已发布[GitHub SPEC #30](https://github.com/liunoly-design/Personal_wiki/issues/30)（ready-for-agent）并读回核验。未开发、安装、调用转写或部署。

## Problem Statement

用户主要通过抖音分享链接收集10–30分钟的视频，需要在Wiki中保留可播放视频、独立完整音频和完整文字，并沿用现有知识处理。电脑空间有限，不希望压缩后仍永久保留两份视频。只保存标题简介或摘要不能代替全文；失败、重启和重复消息不能使已保存资料丢失或重复消耗转写调用。

## Solution

交付0.7：沿用明确Wiki记录入口接收单个抖音分享链接，获取最高1080p的视频。默认压缩归档（最高720p、不放大），可显式选择原画质模式（获取的最高1080p视频不再转码）。从下载源提取完整音频，以可恢复分段方式优先调用codex-asr云端转写候选；合格后接入现有Wiki资料卡、知识编译和全文检索。

同一来源提供视频、完整音频、带粗粒度时间锚的转录全文。默认压缩模式仅永久保留压缩归档视频、完整音频、原始机器稿、来源与处理记录；三类产物发布并核验后，清理临时下载源和转写分片。用户于本次明确确认这是原件永久保留规则针对0.7压缩模式的范围化例外。原画质模式永久保留下载视频，其他既有资料的原件保护不变。

本场景已允许上传音频到云端，无需分说话人或专门删除语气词。机器稿、人工校订和摘要分别管理；不得把语气调整、猜测或摘要冒充完整转录。Codex后端非公开稳定API，不承诺永久可用、免费或零额度；失败不自动切换收费API。

## User Stories

1. 作为用户，我希望发送抖音分享链接，以便直接归档目标视频。
2. 作为用户，我希望沿用现有明确记录指令，以便无需切换入口。
3. 作为用户，我希望默认保存压缩视频，以便减少长期硬盘占用。
4. 作为用户，我希望单次可选择原画质模式，以便对需要的视频保留更高画质。
5. 作为用户，我希望原画质最高1080p且不再转码，以便控制下载规模。
6. 作为用户，我希望压缩最高720p且不放大小视频，以便不浪费空间或伪造画质。
7. 作为用户，我希望看到实际画质和保存模式，以便知道真正归档的内容。
8. 作为用户，我希望独立保存完整音频，以便只听声音或重新转写。
9. 作为用户，我希望音频从下载源提取，以便不受视频二次压缩影响。
10. 作为用户，我希望完整转录10–30分钟的视频，以便直接阅读全部内容。
11. 作为用户，我希望粗粒度时间位置可用于回听，以便核对疑问。
12. 作为用户，我希望疑似缺段、截断或听不清明确标记，以便不把不完整稿当作完整内容。
13. 作为用户，我希望全文独立于摘要保存，以便摘要不代替证据。
14. 作为用户，我希望视频、音频、文字属于同一资料，以便在一处访问。
15. 作为用户，我希望全文继续生成现有资料卡与知识关联，以便沿用Wiki处理。
16. 作为用户，我希望可通过现有查询搜到转录内容并回到来源，以便复用视频知识。
17. 作为用户，我希望正式归档的视频、音频和机器稿不被改写，以便保留该归档版本。
18. 作为用户，我希望人工校订另存且不被重跑覆盖，以便保护修订成果。
19. 作为用户，我希望压缩模式核验成功后清理临时源，以便真正节省空间。
20. 作为用户，我希望失败时保留必要工作材料，以便恢复而不是从头下载。
21. 作为用户，我希望重复消息和同视频不同分享链接复用成果，以便不生成重复来源。
22. 作为用户，我希望之后更换保存模式仍关联同一来源且保留既有正式版本，以便不破坏引用。
23. 作为用户，我希望认证、验证码或额度问题可明确等待，以便处理后继续。
24. 作为用户，我希望临时网络失败有有限重试，以便不无限调用或隐性收费。
25. 作为用户，我希望重启后只续未完成步骤和分段，以便复用已成功结果。
26. 作为用户，我希望收到接收和完成/部分完成回执，以便分别知道三类产物状态。
27. 作为用户，我希望超长、超大视频按既有规则暂停，以便控制磁盘与处理范围。
28. 作为用户，我希望磁盘不足时保留可恢复状态，以便腾出空间后续作。
29. 作为用户，我希望转写接口失效不静默切换其他付费服务，以便掌握费用和数据流向。

## Implementation Decisions

### 入口与范围

- 复用统一记录业务入口、鉴权、任务与回执；不另建独立的抖音Agent或第二套知识引擎。只在明确Wiki记录请求下处理，不因普通讨论中的链接自动归档。
- 记录请求新增保存模式：默认压缩、显式原画质。消息解析和Agent工具使用同一模式语义；模式在接收时冻结，恢复不随之后默认配置变化。具体命令兼容现有记录前缀与别名，开发时验证无歧义。
- 同一条分享文本中的目标URL可提取；每个目标独立任务。新增支持单视频的抖音分享短链/规范链接，不展开作者主页、合集、评论、直播或图文轮播。无法解析为单视频则明确不支持，不将普通博客兜底的简介当完成。
- 获取、跳转及媒体URL继续受允许域名、路径、重定向和网络目标校验约束；凭据、内网地址及任意本地文件不能经链接输入泄露。稳定视频ID须来自可核验平台元数据，不按标题猜测同视频。
- 登录或验证码失败暂停并返回可处理原因；只有明确授权的浏览器范围才可复用会话，不默认读取私人cookies或绕过访问控制。当前场景以非受限视频为目标。
- 10–30分钟是典型范围；超过30分钟或预计1GB沿用先提示规则，未知大小到1GB暂停。确认只适用于原任务/视频及范围，不能突破1080p或扩为主页采集。

### 视频与音频保存

- 1080p/720p按视频显示方向的短边上限判定，保持宽高比、旋转与完整时长，不放大低分辨率素材；实际编码尺寸、帧率、时长及字节大小均记录。
- 原画质模式选择可取得且不超过1080p的最高质量视频流，永久保留其下载字节；不声称拿到作者上传原文件，不保证无水印。没有符合规格的可下载流则等待/失败，不偷偷归档超限视频。
- 默认压缩模式下载源作为工作材料；先验证下载完整并提取音频，再生成最高720p的压缩归档视频。编码参数在非私人样本中固定并记录；所用编码器/版本须可恢复。若压缩失败或未减少字节，不声称压缩成功，不自动转成原画质“全部完成”；保留工作材料供修复或用户显式改模式。
- 完整音频优先保存通用压缩音频（建议M4A/AAC 128kbps，保留声道；实际格式与参数由公开样本兼容性验证固定）。必须覆盖完整源时长，不把短转写分片当音频归档。转写所需解码、重采样和切片使用工作副本，不覆盖完整音频。
- 三类正式产物拥有各自哈希、长度/时长和版本；记录源链接、稳定来源身份、采集时间、实际保存模式、源视频哈希/元数据、转换关系和模型/配置版本。下载源被清理后只保留其哈希等追溯记录，不能宣称还能回读原下载字节或无损还原它。
- 默认压缩产物是“压缩归档视频”，不在模型输入或回执中冒称未经转换的原件。正式压缩归档、完整音频与机器稿发布后只增保留；原件保护例外仅指本任务临时下载源，不影响原画质模式、历史Raw/附件、其他任务或人工内容。

### 分段与Codex转写

- 复用可替换的转写适配边界，首个候选codex-asr；先验证后接入。它复用本机Codex/ChatGPT登录、向云端上传音频，属于非官方桥接；凭据只由运行时读取，不交给模型，不进入日志、Issue、代码或通用备份。
- 以完整音频生成有全局起止时间的分段清单。初始工程配置建议每段不超过5分钟，按可检测停顿切分并保留短重叠；参数经10/20/30分钟实测固定，不能照抄第三方单段时长宣传作为保证。
- 每段保存输入哈希、配置/后端版本、原始响应、转写状态和输出哈希；成功响应先持久化再推进状态。恢复复用已核验成功段，输入/参数变化则新版本，不覆盖旧结果。
- 拼接检查时轴覆盖、静音、空响应、首尾段和疑似截断；只有能够核对同一重叠音频的边界重复才能去重，不能删除原发言的真实重复。原始分段机器响应不改写，全文合稿记录关联。
- 时间锚来自分段起点，明确标为粗粒度；不冒称句级/词级原生对齐。后端返回了流畅文字不等于准确；听不清可识别处标记，模型无置信度时不得伪造置信评分或承诺能自动发现所有漏字。
- 不专门删语气词、不分人、不根据声音断言身份；原始机器稿与人工校订分别保存。完整转录包含原语言表达；既有中文阅读/知识编译规则继续处理，不把转录阶段变成概述。
- 网络超时等临时失败沿用最多五次（含首次）的有限重试；认证/验证码/额度/接口变化进入明确等待或失败，不切收费API。任务恢复不能无记录地刷新重试预算。
- 请求已发出但响应丢失属于未知云结果：记录该状态与可能发生重复请求的事实，通过现有显式恢复入口核对/继续；没有后端幂等保证时不能宣称exactly-once或零重复额度。

### Wiki处理、重复与恢复

- 复用固定Wiki项目与Vault身份校验、受保护发布、历史/并发校验、读回及全文检索。一份来源主阅读页呈现资料卡、完整文字入口和视频/音频引用；不产生三个独立知识来源。
- 完整转录通过现有知识处理生成资料卡、概念/实体/主题关联；摘要与完整正文分开，视频标题、作者说明、模型摘要与用户背景保留来源区分。没有全文时不能从简介编造视频观点。
- 来源稳定ID用于同视频分享短链/长链归并；尚未取得可信ID时，只能按已验证请求/规范URL去重，不能凭标题合并。重复相同模式/配置的成功任务核验后复用；同视频更换保存模式在同来源增产物版本，已归档原画质视频不得被压缩清理删除。
- 分别持久记录获取、音频提取、压缩、分段转写、组稿、知识处理、发布、核验和临时清理。每阶段失败只续未完成工作；文字失败时视频/音频可部分归档，后补文字和知识处理不重新下载全部产物，也不覆盖用户校订。
- 空间预检包含下载源、输出视频、完整音频及工作分片，压缩不等于无需临时空间；无可靠估计时用有限空间/大小守卫，磁盘满明确失败，现有有效文件不当作可删空间。清理允许提前释放已可再生副本的设计须保持恢复可行，禁止删除唯一本阶段输入。
- 全部完成要求三类产物可用、完整文字及知识处理成功、所有正式发布结果核验成功。文字经API读回及检索验证，二进制本地哈希/媒体验证；收到排队/文件存在或模型回话均不足以完成。
- 缺任一产物、编译失败或核验失败均部分完成/等待，回执分列视频、音频、全文与知识处理状态及恢复入口。保持既有接收/完成两阶段回执，不发送未经授权的额外消息。

### 受控临时清理（已获范围化确认）

- 仅压缩模式：三类正式产物、来源引用和知识处理发布并核验成功后，允许清理本任务临时下载源、转写音频分片及其他可再生工作副本。
- 清理目标来自本任务冻结的工作材料清单；核对任务/路径/文件身份，不递归扫删通用目录，不跟随符号链接，不删除正式归档、其他作业、原画质视频或人工修订。
- 源下载字节删除前保留来源元数据、源哈希、转换参数、完整音频、原始机器输出及清理记录；转写音频分片可由完整音频和分段清单重建，机器响应记录不随分片删除。
- 失败、未知发布结果或核验失败保留恢复所需材料；不能为省空间把任务改为完成。清理中断可依据清单逐项核对续作，重复清理不误删；已归档成功但清理失败显示“归档完成，临时清理待恢复”，不重跑云转写。
- 这是未来功能授权规则，本轮规格工作不执行任何删除、下载、凭据读取、云转写或真实Vault写入。

## Testing Decisions

最高验收边界已获用户确认：发送明确Wiki记录请求→处理持久任务→在同一来源打开视频、完整音频、全文→现有查询搜到文字并回到来源→观察可核验回执。优先复用现有入口与正式发布/查询边界，外部下载与转写可注入合成响应；测试断言用户可见成果与持久恢复行为，不断言内部调用次序。

已有回归先例：统一记录工具、受保护归档、人工并发/原件保护、API核验故障、媒体补充、任务预算/清理及跨会话确认。新增功能在这些边界验证，不另造测试专用存储。单元/合成通过、公开平台下载实测、真实Codex转写、真实入口回执分别记录证据。

| 场景 | 验收行为 |
|---|---|
| 默认压缩与原画质选择 | 默认最高720p、显式原画质最高1080p；保持宽高比/旋转，无放大；模式及实际尺寸可读，不伪造原画质 |
| 压缩收益与失败 | 同输入压缩字节小于下载源；未节省、编码失败或损坏输出为未完成，保留恢复材料，不静默改策略 |
| 完整音频与视频 | 可解码播放、时长与源一致到合理媒体误差；尾部测试语句存在；完整音频独立可访问 |
| 三类产物与Wiki处理 | 同一来源关联视频/音频/全文；资料卡及知识处理成功，唯一测试短语可被现有查询检索 |
| 原稿与人工校订 | 机器输出/正式附件哈希不变；校订另存，重新转写和并发发布不覆盖人工内容 |
| 10/20/30分钟转写 | 非私人、许可明确的样本，人工参考覆盖全长；首尾、各段边界无漏段或技术重复，报告中文CER及人工错误清单；不虚称零识别错误 |
| 语义保真 | 不专门删除口头语/否定/情态；合稿不以摘要替代全文，不编造身份、置信度或未说出的事实 |
| 粗时间锚 | 锚点对应已记录音频分段起点，回听能定位对应段，标注粗粒度而非词级准确 |
| 静音/空响应/疑似截断 | 静音不编造正文；有声片段空响应或尾段缺失不能标全部完成，保留问题段 |
| 同视频不同分享链接 | 可信稳定ID下归并同来源；重复成功请求复用已有结果，无重复下载/已完成段转写 |
| 保存模式变化 | 原画质与压缩版本同来源可追溯；重复提交不多建来源，不删除旧正式视频 |
| 压缩源清理 | 三类产物及知识核验成功前源始终保留；成功后仅清允许的临时材料，源哈希与转换记录仍在 |
| 清理路径/身份与并发 | 其他任务/正式Raw/校订/原画质视频不被删；符号链接或文件身份变化拒绝清理 |
| 发布后核验失败 | 内容API不匹配、附件哈希不匹配或查询不可用不标全部完成，临时源不清，恢复先核对已有发布 |
| 清理中断/重复清理 | 根据清单恢复，无误删；已归档成功不再次转写；可独立恢复清理状态 |
| 下载中断/媒体URL过期 | 留工作区未完成字节与状态；验证后续传或重新获取媒体地址，半成品不进入正式附件 |
| 分段/组稿/编译中断 | 重启后复用已核验段和媒体，仅续失败部分；版本变化不覆盖旧稿 |
| 网络五次预算 | 临时失败预算可跨进程核验；不无限调用、不静默恢复为全新预算 |
| 认证/验证码/额度/接口失效 | 明确等待原因与恢复方式，不读未授权cookies，不收费兜底 |
| 云请求未知结果 | 明确记录可能已执行与重发风险，不称exactly-once；成功响应已保存则不重发 |
| 超30分钟/1GB/未知大小 | 继承先确认/达阈值暂停规则；确认不扩大目标、不突破1080p |
| 磁盘不足/损坏输入/无音轨 | 可处理错误，保留有效材料；不得把已有归档删掉或生成空全文冒充成功 |
| 部分完成补全文 | 视频/音频成功而文字失败明确部分完成；补文字及知识处理不重新下载、不覆盖旧校订 |
| 备份恢复 | 临时目录恢复正式压缩视频/音频/文字/元数据哈希和来源引用一致；已清理下载源不能被宣称可恢复 |
| 回归边界 | 既有X/微信/博客、讨论保存、同议题记录和查询行为保持通过；不引入Apple任务写入 |

质量验收先记录CER=(替换+删除+插入)/人工参考字符数、英文/数字/专名单列和边界错误，不以流畅或文件存在替代准确。数值质量阈值尚无本机实测，不伪称已冻结产品门槛；实现首个原型需公开10/20/30分钟结果与人工抽查，若不够完整/可读应如实报告并修复，不能悄换收费服务或降低全文要求。

## Out of Scope
