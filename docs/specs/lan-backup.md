## 端到端行为

1. 备份普通文件的完整字节，包括原件、附件、Markdown、隐藏历史和所有隐藏子目录；保留空目录。受保护层的锁文件不进入恢复成果。
2. 对文件记录大小和 SHA-256，清单内容确定快照 ID。目标逐文件核验后，从 `pending` 原子提交到 `snapshots`；同内容重复备份核验后复用。
3. 不替换或删除已提交快照。断流保留已校验文件，下次同清单只传缺失文件。损坏的已有文件不能通过覆盖“修复”。
4. 存在受保护写锁时非阻塞取得它；全树在哈希和传输前后比较设备、inode、类型、大小、mtime、ctime。创建/删除目录或修改文件均导致失败，不提交发生变化的源。未建立全运行状态的业务事务检查点。
5. 所有文件访问锚定目录描述符；拒绝符号链接、特殊文件、路径逃逸、重复清单条目及缺失父目录。目标锁隔离并发仓库命令。
6. 恢复只允许不存在的新目录，先校验目标快照，再写隔离暂存目录、校验完整结果，以禁止覆盖的原子重命名发布。中断的暂存目录保留，不自动删除任何资料。
7. SSH 使用已有认证，启用 BatchMode、严格主机密钥检查和连接/保活超时。远程命令代码固定，仓库路径与请求通过 JSON 标准输入传递；不读取或保存密钥。
   连接可明确选择独立密钥文件和远端 Python 绝对执行路径；私钥只由 SSH 客户端使用，不进入备份数据或代码仓库。
8. 提交回执丢失时先读取并核验已提交快照；不自动重放未知提交。失败回执说明原因、保留状态和恢复建议。

## 测试 seam 与验收

最高公共 seam 为 CLI 的 `backup / verify / restore / list`，SSH 接收协议作为外部传输边界。使用真实临时文件系统和合成原件，验证往返、幂等、多版本、断流恢复、损坏拦截、源变化、忙锁、路径逃逸和恢复禁止覆盖。SSH 替身运行真实远程程序，只验证协议，不能宣称真实 LAN 登录。

真实验收必须：用户目标目录确定 → Mini 身份/连接确认 → 本机 Vault 备份成功 → Mini 完整哈希核验 → 本机独立新目录恢复 → 内容比对。任务状态以完整证据为准，尚未完成这些步骤时保持开放。

## 边界

- 不备份 `~/.openclaw` 的运行账户、浏览器、宿主配置和私钥，不自动启动恢复任务。
- Mini 上原有视频/音频并不随本机 Vault 链接复制；该媒体需要另一个独立存储备份任务。
- v1 保存文件字节及目录结构；不承诺原始 POSIX 权限、mtime、扩展属性、Finder 标签或资源分叉恢复。恢复文件 0600、目录 0700。
- 无定时、保留删除、空间去重、运行部署和 nashsu 自动接管。不同快照保存独立完整内容；磁盘需有足够可用空间。
- 必须使用支持文件锁、fsync 和禁止覆盖原子重命名的文件系统。SMB 挂载是否具备这些能力需在用户分享盘实测；否则选择 SSH 到 Mini 本地磁盘，失败不降级为覆盖写入。
