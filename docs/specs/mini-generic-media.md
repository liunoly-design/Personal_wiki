# Mini 通用媒体转录（#50）

## 已确认范围

沿用三层入库规格和现有公开接口验收：CLI/持久任务、Mini HTTP 边界、受保护 Wiki 写入与读回检索。此次实现本地音视频、小红书单个视频笔记及 X 来源链内的视频；获取完整媒体、完整本地 ASR、时间戳 Markdown，随后复用 Wiki 编译与关联。只转换不写 Wiki。保留旧抖音接口及现有服务管理路由。

## 实施决定

- 客户端负责平台获取，保留原始响应、来源 ID、选择和下载证据。Mini 不接收任意下载 URL；通用任务只接收已经取得的文件及明确标注为客户端声明的来源。
- 文件提交时建立流式不可变快照，记录 SHA-256、字节数、原文件名。后台任务不重新打开可能被修改的原路径。显式 `--file` 与文字输入分开；音视频补料沿用原 Wiki 任务身份并标注用户提供，不能冒充平台下载。
- `POST /v1/file-jobs`（JSON，幂等键）→ `waiting_upload`；`PUT /v1/file-jobs/{id}/content` 流式上传，校验大小和哈希后原子排队。中断保留同一作业，重传从头开始，不承诺断点字节续传。相同键不同请求返回冲突。
- 共用已有 jobs 表、OS worker 锁和单路 ASR。扩展适配器按 request kind 分派处理及快照，旧抖音严格校验不被放宽。通用结果独立 manifest/markdown/media 路由。
- 服务端和客户端均验证输入哈希、完整解码、音轨/容器/平台声明时长、ASR 段落顺序与首尾覆盖；没有音轨、空稿、缺尾或不完整来源进入待补。首尾容许无语音间隔各 10 秒，段落覆盖不等同逐字人工准确性。
- 通用输入单文件上限 1,000,000,000 字节、30 分钟；超过返回待确认，本轮不增加远端越限审批能力。FFmpeg 处理有时限，ASR 共用现有本地 whisper.cpp；原始 ASR 与机器中文译文分开。本地英文翻译复用 Mini 已有 MLX 配置，不启用云端音频服务。
- 输入与原始 ASR、转码绑定文件和输出哈希保留。重启复用校验通过的阶段；异常恢复仍复用原作业。服务端只存媒体，不写 Vault，不启动通用资料的服务端自动知识增强。
- 结果链接不带 token；客户端使用已配置同源服务和 Authorization，Range 首中尾核对。原始文件保存在 Mini 和客户端私有任务区，Wiki 保存来源包、转录和远端媒体凭据以外的引用。

## 端到端任务顺序

1. 本地音频/视频：文件快照→鉴权上传→单路本地 ASR→只转换→Wiki 读回检索；先证明原件保护、冲突、重启与失败恢复。
2. 小红书视频：精确 note 身份和原始状态→受限公开视频下载→同一接口→完整来源文字与视频稿→Wiki。依赖 1。
3. X 视频：保留连续来源链及引用帖→逐个视频转写→完整 Markdown→Wiki；不把媒体完成误称来源上下文完整。依赖 1。
4. 真实短公开视频、合成语音/视频和全量回归、两路独立规格/标准 review、不可变发布。依赖 1–3。

## 验收

公开接口测试覆盖鉴权、限制、坏哈希/截断、并发重复上传、原件保护、无音轨/缺尾、重新启动与原作业恢复、多个视频，以及 Wiki 发布和检索。真实验收与模拟测试分别记录；未完成的来源不宣称跑通。凭据、签名链接、真实媒体和运行状态不提交。

## 不在本轮范围

视频画面 OCR、直播、DRM、账号批量抓取、音乐-only 的语音补造、说话人识别、Mini 接管 Wiki、越限审批 UI、外部自动通知。Live Photo 保留待补，不把封面当完整视频。
