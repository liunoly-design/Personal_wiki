# 0.7.8 X 重复正文与任务状态修复候选

日期：2026-10-07。基线：`c98bf2d461064fa3e383c519ef8d87368545c610`（0.7.7）。状态：本机验证候选；部署及真实飞书新入站另行核验。本轮依据用户已报告的问题继续确认，不新增账号登录、外部消息或资料批量修改授权。

## 问题与范围

公开 X 页面可能包含同一目标文章的两份展示，其中一份多保留裸 URL 链接或媒体。0.7.7 选择器将这种差异认作正文冲突；上下文解析又可能选回较少信息的第一份。抓取错误含任务路径时，ID 中的 401/402/403 会被当作 HTTP 状态，误报登录或额度等待。

仅修复公开文章的重复选择和这三个数字的误分类。沿用 [0.4.2 已确认规格](v0.4.2.md) 的采集包、任务状态、来源与原件哈希测试入口。

## 验收行为

1. 同一目标 permalink 的副本，仅正文文本一致、差异为裸 URL 链接/媒体/嵌套引用时，选用一份包含全部已见引用、链接和媒体的完整副本。保留来源顺序，不拼接或编造缺失内容。
2. 没有任何单份包含全部信息、正文确实不同、回复父 ID 相互冲突，或完整副本彼此仍不同，继续拒绝歧义。不得按长度选择不相关正文。
3. 采集选择与最终上下文解析共用选择规则，避免后续解析丢回新增链接或附件；未知回复关系继续显示上下文缺口。
4. 错误路径中的 401/402/403 不触发等待。临时抓取错误按原五次预算重试，失败资料保留。
5. 明确 HTTP 401/403、登录或验证码仍进入登录等待；明确 HTTP 402、quota/capacity 仍进入额度等待。重启不得自动解除等待或刷新预算。
6. 原始 HTML 与成功附件保持原字节；重复调用复用成功采集包。真实资料及状态只留在私有运行目录，不进代码或测试。

## 验证与交付边界

- 使用合成采集与队列失败场景，先复现再修复；复测冲突、嵌套引用、分页、评论过滤、恢复及原件保护。
- 在私有目录只读回放已授权真实 HTML 与附件，默认新选择器直接完成采集，零模型、零外部消息调用；核对既有 Vault 原件哈希。
- 公开页面独立复查仅作当前可见证据，不把没有父 ID/分页信息解释为不存在后续串文。
- 完成代码审查与全量回归后，保留可审阅的 0.7.8 候选。部署会切换不可变 release 并重启共享 OpenClaw 网关；用户本轮“继续确认”不直接代表已执行部署。
