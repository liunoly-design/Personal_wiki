# Wiki 独立安装、自检与配置回退（首个可验收任务）

日期：2026-10-06。已确认：用户回复“可以实现并验收”，承接上一轮第一项小任务。范围不扩展为录音、维护或定时备份。

## Problem Statement
现有安装器依赖固定本机路径、已有 PGTD 范围和 wiki Agent，无法为自己的新库安全安装；失败可能留下半安装配置。

## Solution
提供显式配置驱动的安装/自检/配置回退入口，使用已有 OpenClaw、nashsu 与模型运行时。全部验收在隔离宿主配置与合成新库中执行。

## User Stories
1. 作为用户，我希望自己指定库与私有状态位置，以便独立使用 Wiki。
2. 我希望明确指定飞书账号、入口 Agent、用户及会话范围，以免继承 GTD 授权。
3. 我希望自己指定 Python、Codex 和模型，以便复用已有依赖。
4. 我希望检查依赖和固定库，以便知道缺少什么。
5. 我希望安装失败保留原配置，以便继续使用其他插件。
6. 我希望重复安装复用成果，以免产生重复配置。
7. 我希望配置回退保留资料和状态，以免恢复时丢失原件。
8. 我希望其他程序修改配置时拒绝回退，以免覆盖新设置。
9. 我希望凭据仍由宿主管理，以免进入源码、输出和备份清单。
10. 我希望无需 PGTD/Apple 即可安装，以便独立交付。
11. 我希望使用指定 Wiki Agent 的凭据，以免读取固定 Agent 的账户。
12. 我希望报告区分安装、API、模型认证和真实收集，以免将健康检查当作完成。

## Implementation Decisions
- 新入口用私有 JSON 设置及 install/check/rollback 命令。旧安装器保留为历史兼容入口。
- 复用插件和受保护发布流程，不创建第二套知识引擎。
- 宿主 OpenClaw、nashsu 注册新库、飞书账户和入口路由须事先由用户配置；新增所选 Agent 的目录和工具配置，不自动扩大既有账号路由。
- 不自动安装依赖、下载模型、复制认证、启动服务、重启正式 Gateway 或调用模型。
- 在私有状态目录复制发布所需代码；配置持久备份、排他锁、基线核对、原子替换；宿主验证/加载失败恢复原配置。未知并发变更拒绝覆盖。
- 回退只恢复精确原宿主配置，不删除 Vault、状态、发布代码或凭据；幂等安装只复用仍与设置及源码对应的成果。
- 模型凭据解析使用指定 Agent 与宿主配置，不按固定 wiki 身份读取。
- 基础自检只读，Python依赖/CLI版本探测；可选择仅本地 nashsu API 读回。模型认证、额度、飞书真实入站保持未验证状态。
- 安装器不创建或修改知识正文；新库由 nashsu 初始化，本任务检查并绑定它。

## Testing Decisions
已获上一轮确认的最高边界：执行安装入口→隔离配置/新库→插件加载与自检→失败原配置字节恢复。测试经 CLI 与安装公共入口验证；必要故障注入使用外部 CLI 可执行替身。验证重复、原件/其他插件不变、并发、符号链接、缺依赖、校验/加载失败回退、显式回退拒绝覆盖后续编辑。最后使用真实 OpenClaw CLI 与已有 Python 做隔离验收，不访问私人账号。

## Out of Scope
完整 OpenClaw/nashsu 首次安装、登录/飞书账号开户、正式部署、真实消息、模型调用、资料备份恢复演练、跨设备备份、录音、维护扫描、Apple操作。
