# 0.3.0：完成收集流程并提供完整中文阅读

状态：Q1–Q6 及任务拆分已确认；已按 to-spec 发布为 [Issue #2](https://github.com/liunoly-design/Personal_wiki/issues/2)，标签 ready-for-agent。11 项开发任务已发布为 #3–#13，编号、依赖及复用方式见 [任务清单](../plans/v0.3.0-tickets.md)，尚未实施或验收。下文保留规格发布时的正文；任务审阅状态以本段及任务清单为准。

## Problem Statement

当前 personal-wiki 0.2.0 已有单条 X/微信采集、Flash 基础解释及 nashsu 编译，但原首版要求尚未全部完成。用户还需要保存普通国外博客，把新英文文章完整翻译为中文，并将正文忠实整理为易读 Markdown。现有中文摘要无法替代全文译文，模型或附件失败也不能使已归档资料丢失。

## Solution

交付 personal-wiki 0.3.0：完成既有首版收集要求，支持文本、X、微信及普通国外博客，保留原件，生成独立的中文阅读正文和可追溯资料卡、概念、实体与关联。现有 OpenClaw Wiki Agent 调用按用途封装的业务工具，工具优先使用 nashsu HTTP API，复用现有编译能力。英文全文翻译使用 Codex CLI 的 gpt-5.6-terra，翻译失败时继续原文知识加工，之后只补失败翻译。

本规格扩展 [首版规格 #1](https://github.com/liunoly-design/Personal_wiki/issues/1)，不取消或降低其中已有要求。版本顺序已确认：0.3.0 收集与中文阅读，0.4.0 查询，0.5.0 讨论。

## User Stories

1. 作为用户，我希望从飞书记录文本、X、微信和普通国外博客，以便统一归档资料。
2. 作为用户，我希望保留现有记录指令及收集别名，以便沿用已确认的入口。
3. 作为用户，我希望一次提交多个链接，以便逐项获得成功、部分完成或失败结果。
4. 作为用户，我希望个人补充背景与原文分开，以便不混淆作者表达和个人判断。
5. 作为用户，我希望永久保留原始抓取结果、正文提取稿和附件，以便核对来源。
6. 作为用户，我希望记录来源 URL、采集时间、稳定标识和哈希，以便验证完整性。
7. 作为用户，我希望重复链接返回已有归档，以便避免重复下载或模型调用。
8. 作为用户，我希望明确重新收集时为变化内容创建新版本，以便保留旧证据。
9. 作为用户，我希望原文入口和资料卡使用可读英文短文件名，以便查找和维护链接。
10. 作为用户，我希望保留 X 目标帖、同作者连续串文和引用帖，以便理解上下文。
11. 作为用户，我希望排除其他评论，以便避免把评论混入正文。
12. 作为用户，我希望需要登录时使用获准的本机会话，并在失效或验证码时暂停，以便自行恢复后继续。
13. 作为用户，我希望保存正文图片、视频及标题简介，以便离线查看资料。
14. 作为用户，我希望视频最高 1080p，超长或超大时先确认，以便控制存储和下载规模。
15. 作为用户，我希望附件失败后可单独补下载，以便不重复处理已成功正文。
16. 作为用户，我希望新收集的英文文章提供完整中文译文，以便直接阅读全文。
17. 作为用户，我希望译文链接回英文原件，以便核对措辞和事实。
18. 作为用户，我希望排版只修复标题、断行、列表、表格、引文、图片、公式和代码结构，以便保留原文顺序和含义。
19. 作为用户，我希望代码、URL、引文对应关系和附件位置得到保留，以便整理后仍可使用。
20. 作为用户，我希望采用 Codex CLI 的 gpt-5.6-terra 翻译，以便沿用现有订阅登录。
21. 作为用户，我希望全文译文与来源卡摘要分开，以便区分原文阅读和知识提炼。
22. 作为用户，我希望翻译失败时原文继续生成知识，以便不耽误资料整理。
23. 作为用户，我希望回执明确中文阅读尚未完成，并能单独补译，以便知道实际进度。
24. 作为用户，我希望既有归档保持现状且不安排补译，以便本次升级聚焦新资料。
25. 作为用户，我希望名词基础解释先保存，再生成文章关联，以便区分通用解释与本文观点。
26. 作为用户，我希望来源卡包含结论、摘要、观点、事实证据及来源，以便快速回顾。
27. 作为用户，我希望保留争议观点各自的来源和日期，以便独立判断。
28. 作为用户，我希望手写及标记保留内容受程序保护，以便自动加工不覆盖个人知识。
29. 作为用户，我希望综合文章和大范围调整进入待审，并通过编号应用、跳过或稍后处理，以便控制知识修改。
30. 作为用户，我希望临时失败最多尝试五次、额度不足时等待，以便恢复处理而不自动增加付费服务。
31. 作为用户，我希望应用重启或处理被中断后能恢复未完成步骤，以便不丢原件、不重复已完成加工。
32. 作为用户，我希望收到接收和完成两阶段回执，以便查到标题、摘要、位置、附件及待审事项。
33. 作为用户，我希望查询和讨论按后续版本开放，以便本版先完成收集与中文阅读。
34. 作为用户，我希望以后再备份到局域网另一台 Mac mini 的硬盘，以便本版不引入未配置的远端备份任务。

## Implementation Decisions

- **复用与边界**：以已安装 nashsu 0.6.11 为验证基线，按用途封装记录、处理进度和待审操作。现有 MCP 是 HTTP 包装，当前固定 OpenClaw 入口直连 HTTP；模型不直接持有令牌或任意文件写入权限。固定项目 ID 并验证目标 Vault，防止桌面切换项目导致写错知识库。
- **调用事实**：来源扫描只表示发现和排队，不能据此返回加工成功。nashsu 0.6.11 的文档解析和知识编译部分属于桌面流程；缺少独立 HTTP 翻译/转换/直接页面写入接口时，通过本地适配衔接现有能力。不得将内置 Agent 间接写页当作确定性的存储 API。
- **模型分工**：新增全文翻译逐次指定 gpt-5.6-terra，使用已有 Codex CLI 订阅登录。Flash 基础解释和现有 nashsu 知识编译的模型职责保持现状；本规格不把知识编译模型一并切换。模型不可用和额度不足进入明确等待/失败状态，不自动改用付费 API。
- **原件与派生内容**：原件、提取稿、排版正文、完整译文及资料卡可分别识别；派生内容记录对应来源标识、原件版本、生成模型和处理状态。译文与原文是一份来源的不同表示，避免当作两份独立证据重复编译或计数。
- **翻译排版**：完整保留内容和顺序，不摘要化、不添加原文没有的观点。代码和公式保留语义，URL 与本地附件引用有效；长文按可恢复单元处理，完整性检查通过后才标记中文阅读完成。结构检查不能替代译文语义抽样。
- **阶段状态**：采集、归档、附件、翻译、知识编译分别记录结果。翻译失败不阻止原文知识加工；正文、翻译或附件未完成均在回执中单独标明。补译只重试翻译，补附件只重试失败附件，不重复抓取和知识编译。
- **重复与版本**：重复消息及链接复用已有任务/资料；重新收集只为变化内容另存版本。既有英文归档不自动补译，不安排批量迁移；重复投递旧链接不能因缺译文触发模型调用。
- **采集**：优先复用现有平台与通用文章提取库。普通博客按单篇 URL 处理；X 包含目标帖、同作者串文和引用帖，其他评论不入正文。抓取不完整时保留实际所得并说明缺口，不根据标题推断缺失原文。
- **附件**：视频最高 1080p，不展开播放列表，不转录或推断未转录内容。超过 30 分钟或预计 1 GB 先保存正文及元数据并询问；未知大小达到 1 GB 暂停。正文成功、附件失败为部分完成。
- **恢复**：统一临时网络失败的总尝试预算，最多五次含首次，避免多层重试相乘。登录/验证码、模型额度不足分别等待；登录恢复后续作。处理被打断时保持已完成步骤和原件哈希，跨进程并发受控。
- **知识写入**：复用来源卡、概念、实体、主题关联与 Review。手写/保留段落及原件由程序保护；归属不明或并发修改时转为待审。自动生成部分更新保留历史，冲突观点并列来源与日期。
- **待审操作**：统一用户可见编号关联具体建议与受影响版本。应用必须实际完成并验证动作后才标记已处理；跳过/稍后不执行内容修改。HTTP Review 状态更新只标记状态，不能冒充动作执行。无法安全支持的动作保留待审并说明原因；不能默默视作完成。
- **回执**：接受任务后确认收到，结束时按实际阶段结果返回标题、一句话摘要、归档/阅读入口、附件状态和新增待审编号。重投递和回执失败不重跑内容加工；未知投递结果不得宣称已成功送达。
- **未来备份**：目标是局域网另一台 Mac mini 的硬盘，地址、目录、连接方式、周期及保留策略后续确定；0.3.0 不创建相关连接或定时脚本。
- **工程选择**：解析库、浏览器会话接入、原子写入与上游保护适配由实测选择。若上游原样不能保证已确认边界，明确记录缺口并适配；不能仅靠提示词宣称实现保护。

## Testing Decisions

沿用已确认的统一业务测试边界：提交收集/后续处理指令，观察归档产物、原件哈希、引用、处理结果及回执。网络与模型在自动测试中采用确定性样本；再以少量公开或既有已授权样本验证真实集成。已有消息幂等、归档并发与损坏检测、旧版保留、Flash 先保存再编译及插件路由测试继续复用。

测试应验证用户可观察行为，不依赖私有函数或提示词文本。围绕收集流程、受控归档与写入、译文产出、失败续作及待审动作验证：

| 场景 | 可观察验收结果 |
|---|---|
| 文本、X、微信、普通博客 | 原件、正文、附件及资料卡可定位；来源引用可解析 |
| 多链接及个人背景 | 每条来源独立结果；背景不混入原文；单项失败不丢其他成功项 |
| X 串文/引用/评论 | 同作者串文及引用保留，其他评论排除，缺失上下文明示 |
| 英文长文 | 各章节完整翻译，顺序和语义保留；存在可访问英文原件入口 |
| 表格、图片、代码、公式、链接 | 对应结构与内容保留；附件路径有效；未增加无来源观点 |
| 中文原文 | 忠实排版，避免不必要的翻译调用 |
| 旧归档重复提交 | 返回已有结果，原件不变，不调用翻译模型 |
| 新来源翻译失败 | 知识编译仍可完成，中文阅读明确未完成，单独补译不重复其他步骤 |
| 部分附件失败 | 原件与成功附件保留，仅补失败项 |
| 显式重新收集 | 内容变化则新旧版本均可查，旧哈希不变 |
| 临时网络失败 | 总尝试最多五次，停止后结果明确，不出现嵌套重试倍增 |
| 登录/验证码/额度耗尽 | 正确等待，恢复后续作，不自动切换付费 API |
| 视频阈值 | 超长/预计超大先暂停，未知大小达到阈值即停，不到下载结束才检查 |
| 原件/手写/保留段落 | 编译、待审及并发场景中内容受保护；无法判断则不覆盖 |
| 待审应用/跳过/稍后 | 仅影响指定项；实际动作失败不标成功，修改有历史 |
| 桌面切换项目、应用关闭 | 不误写其他项目；明确等待或失败；原件与任务保留 |
| 处理中崩溃与回执失败 | 已完成步骤不重复，未完成步骤可恢复；结果状态真实 |
| 飞书真实链路 | 以实际入站消息关联接收、任务与最终回执；不得用直接函数调用替代 |

真实私人登录、外部消息及运行配置变更继续遵守既有授权边界。只完成离线测试时应明确记录尚未完成真实验收。

## Out of Scope

- 查询为 0.4.0，跨资料讨论与讨论结论保存为 0.5.0。
- PDF/Office/电子书/独立图片文件导入、音频及视频转录、周期知识 Review、GTD 行动交接。
- 抖音、YouTube、自动展开播放列表。
- 对既有归档补译或批量迁移。
- 局域网远端电脑接入、定期备份脚本、同步配置。
- 本轮自动升级 nashsu、启用向量搜索、付费搜索或自动切换新的付费模型服务。
- 综合文章及大范围重构的自动应用，直接完成或删除 Apple 任务。
