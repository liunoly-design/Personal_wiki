本版沿用已有查询/阅读/讨论/待审入口。[SPEC](specs/v0.6.2-continuous-topic.md) · [任务](plans/v0.6.2-plan.md) · [测试与部署证据](research/v0.6.2-acceptance-2026-10-03.md)。D/K都使用真实回执编号，尖括号是占位，不要原样发送。

## 飞书测试与日常使用

在已授权的小婕会话发送：

```text
小婕 wk 讨论：Opus 工作流适用于哪些场景？
用户判断：先在小范围试用。
```

预期返回 `D-…`、作者观点/模型推断/未决问题、来源与阅读命令。普通讨论不保存正式知识。核对实际已读来源，再保存：

```text
小婕 wk 保存结论：<D编号>
```

预期：通过nashsu读搜核验、稳定 `K-…` 阅读命令、文档路径及保存条目编号。复制回执阅读命令检查正文，分页按回执“继续”命令阅读。

继续同一议题（退出/重开模型会话或服务重启后仍使用同一D；限定原授权用户和飞书会话）：

```text
小婕 wk 讨论：<D编号> 大型组织有哪些不同限制？
用户判断：大型组织暂不直接推广。
小婕 wk 保存结论：<D编号>
```

上面两条分别发送。预期第二次保存的K与首保存相同；文档保留先前判断，新判断按新日期/来源并列。再发送同一“保存结论”且没有新回合，预期返回已有记录，零重复条目。手动在Obsidian加一段“手写验收保留”，新讨论后保存，预期手写原文仍在，修改前全文有历史。

明确另开记录（仍属于同一个D，之后保存默认接着新篇）：

```text
小婕 wk 新记录：<D编号>
```

预期新K，旧篇全文不变；新篇从该议题已讨论内容形成首条记录。新议题使用 `小婕 wk 新讨论：新问题`，获得另一个D；同名标题也不会自动合并。

在飞书回复要保留的那条小婕消息，发送：

```text
小婕 wk 保存
```

预期原回复正文及原始消息JSON保留，不调用模型重写。若被回复内容与当前用户/会话的已登记Wiki讨论回执完全匹配，追加到同议题文档；否则保持独立的“未核验模型回复”归档。原回复的数字/政策/建议不自动成为作者证据。重复回复同一目标保存，原回复只保留一次。

结束：`小婕 wk 结束讨论：<D编号>`，不会自动保存。要恢复同议题，明确使用该D继续。综合仍使用 `小婕 wk 综合：<D编号> 标题`，先查看待审再决定是否应用；不要把返回待审编号当作发布成功。

## 限制与验收边界

- D跨模型会话持久保留；跨飞书用户/会话不隐式绑定，不按标题猜测。0.6.1旧成果按原成功保存请求身份延续最新已核验文档，不自动合并其他旧篇。
- 追问模型上下文为最近20回合，完整回合仍持久保存。已读证据最多20片段/64KiB；保存候选最多64KiB，长议题请分批明确保存。模型可能误判语义，引用校验不替代人工阅读。
- 合成测试证明存储/路由行为；实际飞书入站、显示、模型观点与来源语义须由用户按以上步骤验收。开发者未代发消息、未批准真实提案、未写正式Vault的验收正文。
- 录音、独立安装、自动知识维护、跨PGTD保存不在本版。

## 失败恢复

1. API读搜失败时，不把报错当作“没有落盘”。保留原命令和D；API恢复后重发相同“保存结论/新记录”。原回复保存必须仍回复同一条目标消息。已有冻结候选会被核对，不重新生成或追加两次。
2. 同议题“尚未核验”时，先恢复原未完成保存；不要用“新记录”绕过它。后续讨论可继续，恢复完成后再保存后续回合。
3. 陈旧/并发冲突时，停止对受影响文档的编辑，先备份Vault和Wiki私有状态。保留 `.personal-wiki/topic-actions/<完整保存键>/intent.json`、`before.md`、`displaced.md` 及当前正文。`before.md`是修改前全文，`displaced.md`保留编辑器旧inode上的实际写入；不要删除日志或用旧历史直接覆盖现文。
4. 先对比四份内容并明确选择如何合并；待核验条目需按保存键核对，冲突路径不会自动重写。可将该条回执和文档路径交给开发会话做针对性恢复；未知结果不能直接重新创建同名页。

## 回退到0.6.1

先确认没有活动OpenClaw/Wiki任务；将私有状态与Vault备份到用户指定的位置。以下只切Wiki插件加载路径，保留其他模块当前配置及所有文章/历史：
