# Mac mini 迁入与 X 采集修复

日期：2026-11-01。范围：用户要求先迁移 Wiki，并比较本机与 Mini 处理方式；同时调查抖音/X 常见失败。以下区分数据迁入、代码验证与生产接管。

## 迁入结果

Mini 的 `/Users/mac/Documents/Personal-Wiki` 已有完整 0.7.8 项目和 Git 历史；Vault 在 `/Users/mac/Documents/Personal-Wiki-Vault`。现有 Mini 备份仓库保留。

Vault 从完整核验的快照排他恢复，回读核对 1,249 个文件、386,372,791 字节。保护锁文件不属于知识备份。旧业务状态独立封存，3,676 个文件、21,473,641 字节，复制前后源稳定，目标全部文件哈希一致；包含未完成任务、去重凭据、讨论、保存记录及恢复材料。详细清单、快照 ID 与私有回执仅在两机迁移目录保存，不提交到 Git。

旧业务状态未作为新端活动队列加载；未复制浏览器登录、宿主凭据或整份 OpenClaw 配置，未重发飞书回执。本机原件、任务和配置保留。此阶段是经校验的迁入副本，不能称为 Mini 已接管生产处理或 dots 已验收。

## 处理位置建议

实测硬件为本机 M1/8GB、Mini M4/16GB；Mini 已运行原生媒体处理服务。建议主库和生产写入都在 Mini 本地，本机用于发起、阅读和人工辅助。尚未做两机相同任务的速度对比。

本机辅助生成候选与存储位置可以分开，但发布仍通过 Mini 的受保护入口。两台电脑直接修改同一共享目录会引入网络中断与并发写入问题，不作为默认方案。助理编排和云端模型计算也不等于全部计算在 Mini 的芯片上执行。

## 故障调查与修复边界

X 两个旧缓存页面含有真实目标链接，但首个帖子链接来自正文，旧上下文分组据此错认身份，误报可能需要登录。修复使用时间戳链接作为有证据的来源身份；无时间戳时保留全部候选，继续拒绝冲突副本。采集、上下文与嵌套引用使用同一规则。原 HTML 与正文中的其他链接保留。

回归经公开 capture 入口覆盖正文提前链接其他帖、其他帖引用目标、嵌套引用身份、无时间戳冲突副本；每项修复前失败、修复后通过。两个真实缓存回放恢复目标识别，各自仍有一个上下文缺口；没有重新抓取、调用模型或发布正式知识，不能据此宣称 X 全链路恢复。

抖音的一项通用 SOURCE_UNAVAILABLE 实为视频 2,470.8 秒，超过既定 30 分钟确认门槛。服务将 ConfirmationRequired 映射成通用代码，用户看不到实际原因；未绕过门槛或重交任务。另一项 373.538 秒视频在下载阶段失败，现有日志仅记异常类型，具体网络/下载原因尚未证实。此前一个成功任务已由当前客户端验证完整 manifest/来源/媒体证据与 Markdown 哈希，不能把旧的“缺证据”记忆当作当前状态。

## 新电脑兼容性发现

Mini 已按项目 requirements 在独立 `.venv` 安装采集依赖。首次验收发现代理模块硬编码本机的 OpenClaw 安装位置；现支持显式 `packageDir` 或 `WIKI_OPENCLAW_PACKAGE_DIR`，原默认行为保留。Mini 可配置 `/opt/homebrew/lib/node_modules/openclaw`，不复制本机宿主目录或凭据。

三个附件合成测试原先替换模块属性，却没有替换 download 默认参数已绑定的 DNS 函数，意外依赖真实网络。已通过原有 resolver 参数显式注入模拟解析器；在强制返回假地址的隔离环境下，附件行为测试仍能验证限额、续传和 ETag，不触发真实 DNS。

Mini 当前将 `x.com` 和 `video.twimg.com` 解析到 `198.18.*`，生产采集的非公网地址保护会拒绝。测试隔离修复不代表这个实际网络条件已解决；正式启用 X 采集前须配置相应域名的真实 DNS/代理路径并实测，不能放宽 SSRF 校验。当前未修改全局代理配置。
