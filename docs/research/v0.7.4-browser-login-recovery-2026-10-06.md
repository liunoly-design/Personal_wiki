# 0.7.4 专用浏览器登录恢复

日期：2026-10-06。实施基线：`a39c694` / 0.7.2；最终运行版本：0.7.4。

## 原因与修复

用户执行专用 X 登录命令时，`Page.goto` 返回 `net::ERR_PROXY_CONNECTION_FAILED`。已在同机原脚本复现。系统代理为 `127.0.0.1:7897`，代理请求 X 成功；专用浏览器的 `MAP * ~NOTFOUND` 同时拒绝了本地代理地址。

- DNS 规则仅增加 `EXCLUDE 127.0.0.1`；HTTP 请求继续要求 HTTPS、原平台域名白名单及443端口，仍拒绝页面访问本地 URL。
- 单独截获全部 WebSocket，不连接服务器。合成对照证明：只有 DNS 排除而没有此限制时，页面能连接本地 WebSocket 服务。API 行为依据 [Playwright WebSocketRoute 文档](https://playwright.dev/python/docs/api/class-websocketroute#web-socket-route-connect-to-server)。
- 终端输入在独立 daemon 线程等待，仅设置 Event；Playwright 主线程继续处理网络回调。合成对照证明：旧 `input()` 等待会让后续登录 API 路由停住，修复后等待期间仍能处理请求。

没有自动登录、解决验证码、导出Cookie、修改任务状态或代发飞书命令。沿用任务原有隔离配置。

## 验证

1. 现场原登录命令红灯：相同代理错误。仅排除代理地址后，隔离 Chrome 的 X 首页、登录页及用户指定目标均返回HTTP200；最终0.7.4发布脚本亦到达终端登录提示。
2. 新增 `tests/test_browser_session.py`，使用临时隔离 Chrome、合成 X/API 页面和本地监听器，不接触账户或真实浏览器配置。真实函数验证等待输入时API仍响应、页面不连接本地 WebSocket。恢复旧阻塞输入、移除WebSocket限制的内存对照分别红灯；最终实现绿灯。
3. Node 125项、Python 63项（启用浏览器回归）通过；最终测试断言加强后单独回归通过，`git diff --check`通过。
4. Standards / Spec 两个子代理复审：源码无剩余阻断项；测试关于启动计时和回调见证的两项建议已落实。
