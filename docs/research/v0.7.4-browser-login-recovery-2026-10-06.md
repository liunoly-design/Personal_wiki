# 0.7.4 专用浏览器登录恢复

日期：2026-10-06。实施基线：`a39c694` / 0.7.2；最终运行版本：0.7.4。

## 原因与修复

用户执行专用 X 登录命令时，`Page.goto` 返回 `net::ERR_PROXY_CONNECTION_FAILED`。已在同机原脚本复现。系统代理为 `127.0.0.1:7897`，代理请求 X 成功；专用浏览器的 `MAP * ~NOTFOUND` 同时拒绝了本地代理地址。

- DNS 规则仅增加 `EXCLUDE 127.0.0.1`；HTTP 请求继续要求 HTTPS、原平台域名白名单及443端口，仍拒绝页面访问本地 URL。
- 单独截获全部 WebSocket，不连接服务器。合成对照证明：只有 DNS 排除而没有此限制时，页面能连接本地 WebSocket 服务。API 行为依据 [Playwright WebSocketRoute 文档](https://playwright.dev/python/docs/api/class-websocketroute#web-socket-route-connect-to-server)。
- 终端输入在独立 daemon 线程等待，仅设置 Event；Playwright 主线程继续处理网络回调。合成对照证明：旧 `input()` 等待会让后续登录 API 路由停住，修复后等待期间仍能处理请求。

没有自动登录、解决验证码、导出Cookie、修改任务状态或代发飞书命令。沿用任务原有隔离配置。

3. Node 125项、Python 63项（启用浏览器回归）通过；最终测试断言加强后单独回归通过，`git diff --check`通过。

## 0.7.5：登录窗口关闭后的退出处理

2026-10-06用户反馈0.7.4已到达登录提示，但窗口关闭后 `Page.wait_for_timeout` 抛出 `TargetClosedError`。之前仅验证等待期间网络交互，没有覆盖关闭窗口这一路径。

新增真实隔离Chrome合成回归：分别通过CDP关闭页面、关闭浏览器；0.7.4内存对照均复现相同异常。0.7.5记录页面及context关闭事件，登录等待仅在有关闭证据时结束，输出“登录是否完成尚未核验”，仍执行context清理并释放配置锁。未关闭时的其他错误继续抛出；正文采集分支不吞异常。关闭窗口不登记登录成功、不改变等待任务或续作权限。

最终Python64项（含两项真实Chrome合成回归）通过，插件隔离加载检查及diff检查通过。Standards与Spec复审无阻断项；回归增加指定关闭信号和未核验回执断言。新不可变0.7.5已部署，旧版本保留，私有登录入口已指向0.7.5。目标任务JSON哈希仍与修复前一致、状态仍为waiting_login；配置锁可再次取得。真实账户登录与原飞书会话授权续作仍待用户完成。

## 0.7.6：登录按钮后的账号表单

用户进一步反馈窗口自行关闭、无法点击登录。后续同机0.7.5窗口可持续运行，但进程存活不能证明登录可用。截图及临时隔离配置中的真实点击复现：从指定X页面选择“使用用户名或邮箱登录”后出现“Something went wrong”，没有账号输入框。请求失败日志定位到 `jf.x.com/onboarding/web`，该平台登录组件被原域名白名单及DNS规则拒绝。

0.7.6仅增加明确的 `jf.x.com`；仍通过公共地址解析和固定DNS地址、HTTPS/443、无URL凭据的生产请求检查，WebSocket仍不连接服务器。登录模式不再采集响应正文，正文抓取模式保留原逻辑。维持从任务原URL打开；直接打开登录路径的候选在短时实测中未出现表单，未纳入最终实现。

新增真实Chrome合成回归，保留生产授权处理函数，仅以合成HTML替换通过检查后的网络传输，验证 `jf.x.com` 内嵌账号框可见。旧白名单对照红灯，最终实现绿灯。全Python65项、Node125项通过；撤销候选导航后再次运行三项浏览器回归通过，插件隔离加载检查及diff检查通过。Standards/Spec复审无阻断项。

真实网站的临时隔离配置对照表单成功出现。部署新不可变0.7.6后，使用用户原隔离配置、生产browser_html函数再次打开指定页面；一次性诊断包装仅点击初始账号登录入口、等待并截图空账号框，不输入或提交任何账户信息。截图证实“电子邮箱或用户名”字段已可见且聚焦，窗口保留供用户手动登录。诊断脚本及截图保留在本机私有运行目录，不进入仓库。旧窗口由本次持有的终端会话按回车关闭，未终止其他Chrome进程。

实际插件0.7.6 / loaded，网关 `ok=true`；私有正常登录入口已指向0.7.6并通过zsh语法检查。目标任务状态仍waiting_login、JSON SHA256与修复前一致。此次验证覆盖账号表单展示，不表示账户认证、验证码、飞书续作或归档验收完成；后续仍由用户完成认证，并在原飞书会话发送原任务的“登录继续”。
