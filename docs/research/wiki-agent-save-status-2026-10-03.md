# Wiki Agent 过期保存状态说明修复

## 故障与证据

0.6.2 插件已本机部署。真实用户曾通过明确回复保存口令收到保存完成回执，后续原生阅读也成功；但另一条普通确认消息由入口委派 Wiki Agent，返回知识卡并声称 Vault 尚未配置。

只读核对显示原保存记录 complete、物理 Markdown 存在、nashsu 回读正文哈希与本地一致、搜索可见。此结果证明此前原回复已保存；不证明后来生成的新摘要卡被保存，也不证明模型中的政策和数字正确。

根因：运行目录中 wiki/AGENTS.md 保留“实际 Vault 路径和摄取工具尚未配置”，xiaojie/AGENTS.md 也保留“Wiki 的实际 Vault 摄取流水线仍未接入”。普通 Agent 据此生成错误状态，没有调用保存用途工具。“系统内固化”没有可核对的持久结果。

## 本机修复

只替换两个运行 AGENTS.md 中与 Wiki 接入和状态报告有关的段落，其余文本保持原样。修改前分别在运行目录保存权限0600备份 `AGENTS.before-wiki-status-20261003T055233Z.md`。反向替换校验可精确恢复每份原文件，GTD 操作边界及其他说明保持不变。未写用户知识正文、未发送飞书消息、未重启共享网关。

Wiki Agent 的当前指令要求：

- Wiki 已通过 personal-wiki 和 wiki_* 用途工具接入本机 Vault；未调用工具或子会话缺工具不能推断整条流水线未部署。
- 保存前传可信的原用户消息 ID 给对应用途工具，由服务端验证原消息；不能转用任意文件写入。
- 只有成功工具结果及核验/阅读入口才报告保存完成；未调用工具的卡片只能称草稿，不能称系统内固化或已归档。
- 回复目标发送“小婕 wk 保存”保存指定全文；“小婕 wk 保存结论：D-实际编号”保存讨论结论。无对应 Wiki 原消息的普通“确认执行”不从旧聊天推定保存授权。
- 模型回复保存不等于政策、数字和来源已核验。

入口 Agent 要传原用户消息 ID，核对 Wiki 工具成功结果后报告状态；明确 Wiki 命令落入普通聊天时排查入口，不能继续用“流水线未接入”解释。

## 检查与限制

两份运行文档的过期句子均移除，相关新边界存在，非目标文本反向替换一致。仅修改指令文档，无代码行为改变；按项目规则检查内容即可。OpenClaw 本机 bootstrap-cache 实现每轮重新加载文件并比较正文，所以长会话后续轮次可读取新说明，无需中断当前任务或清空历史。

尚未代用户发起新的 Wiki 保存或普通确认消息。下一次真实回复的语义仍需用户核对；提示词不能替代工具鉴权、幂等或物理结果核验。
