# 0.6.1 回复续聊与原回复保存验收

## 原因与结果

真实飞书追问的 parent_id 指向已登记 Wiki 讨论回执，但 0.6.0 只接管带口令的消息，普通追问被一般 Agent 回答。其长分析未进入 Wiki 讨论上下文，不能通过旧 D 的保存结论包含它。

0.6.1 对已登记、同用户/会话、own app 发出的完整 Wiki 回执进行匹配，再把普通追问加入所回复的 D；明确回复“小婕 wk 保存”则保留指定回复全文。原 JSON、Markdown 和带未核验标识的阅读页只增发布，API 读搜通过才完成。不会重新分析原回复。

## 验证

- Node 97/97；Python 42/42；插件隔离加载通过。
- 真实追问通过 Feishu getMessage 获取原用户、parent 和 own app，复制会话状态至临时目录后 readonly Vault 回放，准确匹配原 D。模型使用确定性替身，这证明入站身份与关系路由，不证明真实模型内容质量或飞书最终显示。未代发消息、未将真实内容写入正式库或仓库。
- 合成样本：原文富文本与 JSON 内容保留、无模型调用、无 parent 拒绝、未知回复不抢占、API故障重启重发与目标编辑后不双建；两个独立 service 通过进程锁隔离状态，busy 后重试均保留恢复记录。
- Spec 与 Standards 双轴复审 a6f1ca6…6d603c7 必须修复项清零；锁代码重复为非阻塞改进项。

## 使用验收

用户在飞书回复原 Wiki 回执直接追问，应仍返回相同 D 和本库引用。回复待保存的长消息发送“小婕 wk 保存”，应收到原样保存、未核验标识和 K 阅读命令。复制阅读命令检查全文；若 API 核验失败，对同一目标重发保存命令恢复。真实用户入站与保存尚需用户执行，不由开发者代发或代保存。
