## 已交付

按 `grill-with-docs → to-spec → to-tickets → implement → tdd → code-review` 推进。规格为 [Issue #14](https://github.com/liunoly-design/Personal_wiki/issues/14)，三项实现任务为 #15、#16、#17。

1. 原始文章保留在 `raw/sources/`，附件保留在 `raw/assets/`。中文全文与来源卡合并在 `wiki/sources/`；概念和实体进入各自的正式目录。
2. 收到任务先持久化。工作区位于 Vault 外，成功阶段可复用。发布后使用 nashsu HTTP API 回读并校验文件哈希，附件本机校验通过后才清理临时文件及活动任务。
3. 启动恢复未完成任务；同时处理两个不同来源，防止同源并发。网络故障有限重试；登录、额度、媒体问题保留任务，进入明确等待状态。
4. 已有知识文件不会被自动覆盖。修改建议放在 `wiki/queries/review-*.md`，完成回执说明待审数量。

原生 HTTP API 无文章写入接口，因此按已确认方案使用薄本机受保护写入层，复用原生 API 的阅读、搜索与核验。

## 迁移中发现并修复的问题

nashsu 的文件监控在删除旧原始资料副本时，会按来源名称连带清理知识页，关闭自动提取不能阻止这个行为。真实迁移曾影响 29 个知识页和一份待审文件；从迁移计划、编译候选原件恢复后，重新通过原生 API 核验。

补丁要求：迁移前暂停文件监控、确认原生变更队列为空；删除过渡副本后再次核验，之后才保存任务完成记录。迁移完成后恢复文件监控，保持自动提取关闭。恢复监控后再次检查，页面哈希无变化，原生变更队列为空。

已通过 API 校验 371 份迁移/恢复页面与 12 份来源的原始附件；YC、GitHub、Obsidian 搜索均返回结果。两条续跑任务也分别完成了原生 API 发布校验。
